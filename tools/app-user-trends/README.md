# 앱 회원·주문 집계 분석

가입 연월별로 내려받은 회원 엑셀을 검증하고 계정·현재 언어·기록 지역별 집계 결과를 생성합니다. 광고 성과 분석 파이프라인과 별도로 사용합니다.

## 데이터 계약

- 파일명은 `YYMM.xlsx`이며 해당 월에 등록한 계정의 목록입니다. 파일명은 스냅샷 월을 뜻하지 않습니다.
- 필수 컬럼: `id`, `locale`, `country`, `city`, `orders`, `reviews`, `shops`, `level`, `disabled`.
- `id`는 숫자 ID 또는 `숫자 ID. 이름` 형태입니다. 결과에는 숫자 ID와 이름 모두 쓰지 않습니다.
- 같은 숫자 ID의 모든 원본 컬럼이 동일한 반복 행만 한 행으로 집계합니다. 값이 충돌하거나 가입월 파일 사이에 ID가 겹치면 실행을 중단해 검토합니다.
- 다른 ID를 이름·이메일·IP 기준으로 병합하지 않습니다. 한 사람이 여러 계정을 보유할 수 있으므로 실제 사람 수로 해석하지 않습니다.
- 언어는 추출 당시 앱 설정값입니다. 과거 가입월별 분류는 당시 사용 언어의 이력이 아닙니다.
- 국가·도시의 수집 기준이 확인되기 전에는 회원 데이터에 기록된 지역으로만 해석합니다.
- 주문·리뷰는 추출 당시 누적값입니다. 빈칸은 의미 확인 전 0으로 바꾸지 않습니다. `shops`는 건수인지 식별자인지 확인 전 합산하지 않습니다.

## 실행

Python에 `openpyxl`이 필요합니다. 원본 폴더와 결과 폴더를 명시합니다.

```powershell
python -X utf8 tools/app-user-trends/analyze.py --input '<원본 폴더>' --output 'outputs/private-app-user-trends/<분석기간>/aggregates' --start YYYY-MM --end YYYY-MM
```

결과는 집계 JSON·CSV와 출처별 파일명·체크섬입니다. 행 단위 개인정보는 쓰지 않습니다. 원본 파일은 읽기만 합니다.

전체 월별 자료임이 확인된 경우에만 `--completeness-confirmed`를 사용합니다. 모든 월의 건수가 같은 경우 내보내기 제한 가능성을 먼저 확인해야 합니다. 빈칸이 0건이라는 사실을 확인한 경우에만 `--blank-counts-are-zero`를 사용합니다.

관리 화면 등에서 월별 조회 건수를 확인했다면 로컬 CSV(`month,total_accounts,approximate,source`)를 `--reference-counts '<파일>'`로 전달할 수 있습니다. 근삿값은 `approximate=true`로 표시합니다. 조회 건수와 파일 계정 수가 다르면 전체성 확인 옵션이 있어도 성장률을 계산하지 않습니다. 월별 총건수만 확보하면 전체 가입 증가율을 계산할 수 있지만 국가·언어별 증가율에는 해당 분류의 전체 건수가 별도로 필요합니다.

성장률은 다음 기준을 따릅니다.

- 전월 대비: 해당 월 계정 수 / 직전 월 계정 수 − 1.
- 전년 동월 대비: 해당 월 계정 수 / 전년 같은 월 계정 수 − 1.
- 연간 대비: 해당 연도와 전년도 모두 12개월이 있을 때만 산출.
- 동일 기간 대비: 해당 연도 1월부터 마지막 확보 월까지와 전년의 같은 월 범위를 비교.
- 전기값이 없거나 0이면 `n.a.`로 남깁니다. 전체성 미확인 시 성장률은 계산하지 않습니다.

Excel 보고서는 Codex 런타임의 `@oai/artifact-tool`로 작성합니다. 해당 런타임의 `node_modules`를 이 폴더에 연결한 뒤 실행합니다. 원본 데이터나 런타임 종속 파일을 저장소에 커밋하지 않습니다.

```powershell
node tools/app-user-trends/build-report.mjs 'outputs/private-app-user-trends/<분석기간>/aggregates/analysis.json' 'outputs/private-app-user-trends/<분석기간>'
```

보고서에는 요약, 월별 집계, 언어별 구성, 지역별 구성, 국가·언어 교차표, 해석 제한이 포함됩니다. 수식 의존성의 재계산, 계정 수 합계, 수식 오류, 시트 렌더링을 점검합니다.

저장 후 원본 체크섬, ID 추출과 독립적인 전체 행 중복 검사, 분류별 합계, Excel 캐시값과 차트를 검증합니다.

```powershell
python -X utf8 tools/app-user-trends/verify.py --input '<원본 폴더>' --report-dir 'outputs/private-app-user-trends/<분석기간>'
```

## 저장 및 확장

공개 저장소에는 분석 코드와 방법만 저장합니다. 실제 결과와 검증 파일은 Git에서 제외한 `outputs/private-app-user-trends/`에 보관합니다. 이 경로는 Git 추적 제외 경로이며 OS 접근 제어를 설정하는 기능은 아닙니다.

이전 가입월 파일을 추가하면 입력 기간을 확장해 다시 실행합니다. 파일 전체성을 먼저 확인한 뒤 연간·동일 기간 성장률을 갱신합니다. 주문 이력이나 AppsFlyer 집계가 추가되면 기존 계정 데이터와 구분된 측정 단위를 유지합니다.

## 주문 집계 파일 분석

회원 목록과 별도로, 월별 주문 집계 엑셀을 분석합니다. 개별 주문 내역이나 회원 식별자가 없어도 국가·도시·주문언어·업종별 주문수, 상태 구성, 취소율과 통화별 완료 주문금액·객단가를 계산할 수 있습니다. 주문 사용자 수, 재주문율, 리텐션은 계산할 수 없습니다.

### 입력 기준

- 파일명 `YYMM.xlsx`는 주문월입니다. 회원 가입월 파일과 별도 폴더에서 관리합니다.
- 한 파일에 한 시트이며, 머리글이 없으면 **첫 행부터 데이터**로 처리합니다. 정확히 일치하는 알려진 머리글만 제외하고, 임의로 첫 행을 버리지 않습니다.
- 9열 형식: `통화 / 배달 국가 / 배달 도시 / 업종 / 주문언어 / 주문상태 / 상품금액 / 최종금액 / 주문수`.
- 도시 없는 8열 형식: `통화 / 배달 국가 / 언어 / 주문상태 / 업종 / 상품금액 / 최종금액 / 주문수`. 9열 형식과 언어·업종·상태의 순서도 다릅니다.
- 도시가 없는 월은 국가·언어·업종 집계에는 포함하되 도시별 추이에서 `n.a.`로 표시합니다. 도시 주문 0건으로 해석하지 않습니다.
- 각 행은 여러 주문의 집계입니다. 행 개수가 아니라 마지막 열의 주문수를 합산합니다.
- 상품금액과 최종금액은 해당 행 주문들의 금액 합계입니다. 이 사실이 확인된 경우에만 `--amounts-are-sums`를 지정합니다.
- 상태는 공란=주문취소, 1=주문접수, 2=주문확인, 3=조리중, 4=배달시작, 5=주문도착, 6=배달완료입니다. 주문도착은 배달완료로 합치지 않습니다. 그 외 코드는 미확인 상태로 분리합니다. 다른 정의는 로컬 JSON의 `--status-map`으로 지정할 수 있습니다.
- 같은 월·통화·국가·도시·업종·언어·상태 조합이 반복되면 자동 삭제하거나 합치지 않고 검토를 위해 중단합니다.
- 최종금액에는 배달비와 할인이 포함됩니다. 회사 매출·이익·정산액과 다릅니다. 상품금액과의 차액만으로 배달비와 할인을 분리하지 않습니다.
- 서로 다른 통화의 금액을 합산하지 않습니다. 완료 금액과 객단가는 상태 6만 포함하며, 객단가는 완료 최종금액 합계 / 완료 주문수입니다.
- 주문언어는 앱 회원의 현재 설정 언어나 국적과 다른 지표입니다. 주문 상태는 추출 시점 이후 바뀔 수 있습니다.

### 실행 및 검증

```powershell
python -X utf8 tools/app-user-trends/analyze-orders.py --input '<주문 폴더>/YYMM.xlsx' --output 'outputs/private-app-user-trends/orders/<기간>/aggregates' --amounts-are-sums --full-month-confirmed
node tools/app-user-trends/build-order-report.mjs 'outputs/private-app-user-trends/orders/<기간>/aggregates/order-analysis.json' 'outputs/private-app-user-trends/orders/<기간>'
python -X utf8 tools/app-user-trends/verify-orders.py --input '<주문 폴더>/YYMM.xlsx' --report-dir 'outputs/private-app-user-trends/orders/<기간>'
```

`--full-month-confirmed`는 제공자가 월 전체 자료임을 확인했다는 뜻입니다. 관리자 화면 총건수와의 독립 대조는 별도이며, 확인한 값이 있을 때만 `--control-total <건수>`를 지정합니다. 이 옵션은 한 달 파일에 사용합니다. 날짜 필터가 주문 생성일 기준인지, 시간대와 추출 시점이 무엇인지도 월별 비교 시 같은 기준으로 맞춰야 합니다.

분석기·Excel 보고서·검증기는 여러 월을 함께 처리합니다. `--input` 뒤에 월별 파일 경로를 공백으로 구분해 전달하면 됩니다. 한 달은 기존 상세 보고서, 여러 달은 월별 추이·국가/언어/업종·도시·통화별 금액 보고서를 생성합니다.

월별 전월 대비는 직전 달, 전년 동월 대비는 정확히 전년 같은 달이 있는 경우만 계산합니다. 월이 누락되었다고 앞의 다른 월을 전월로 간주하지 않습니다. 일평균 주문수는 월 주문수 / 달력 일수로 계산하며 일평균의 전월 증감도 제공합니다. 전체성·추출 조건을 독립적으로 대조하기 전에는 **제공 파일 기준 잠정 증감률**로 표시합니다. 접수·진행 주문의 추출 시점 차이도 함께 고려해야 합니다.

금액 증감은 동일 통화의 배달완료 금액끼리 비교합니다. 국가·언어별 회원 성장률과 주문 증감률은 서로 다른 지표입니다. 연간 및 전년 동일 기간 합계 보고서는 아직 구현하지 않았으며 비교 기간이 확보되면 확장합니다. 연간 비교는 두 해의 12개월 전체, 연중 비교는 전년의 동일 월 범위를 사용합니다.

교체 예정인 월은 `--replacement-pending YYYY-MM ...`으로 지정합니다. 기존 수치를 참고값으로 남기고, 해당 월이 현재 월 또는 비교 기준 월인 주문·일평균·통화별 금액 증감률은 계산하지 않습니다. 새 파일을 받은 후 해당 월 입력을 대체하고 이 옵션에서 제거합니다. 같은 월의 구본·신본을 동시에 더하지 않습니다.

검증기는 원본 체크섬과 첫 행 포함 여부, 모든 집계 행의 보존, 분류별 건수, 통화별 완료 금액, 저장된 Excel 수식 계산값과 차트를 점검합니다. 관리자 총건수 확인 여부도 검증 결과에 별도로 남깁니다. 원본·집계·보고서·검증 결과는 모두 로컬 Git 제외 폴더에 보관합니다.
